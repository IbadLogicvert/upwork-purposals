My Proposed Approach

1. Audit your current handler - signature verification, response timing, and how events map to billing writes. Slow handlers are a top cause of Stripe retries, which look like duplicate events.

2. Add true idempotency - persist each Stripe event.id and short-circuit anything already processed, so replays and retries stop double-writing billing data.

3. Move processing off the request path - ack Stripe with a fast 2xx, then handle the event via a queue so timeouts never trigger retries.

4. Backfill the gaps - replay missed events using Stripe's Events API and reconcile against your billing records so nothing stays out of sync.

5. Add monitoring - log every event, flag failures, and alert on drift so this never silently breaks again.
